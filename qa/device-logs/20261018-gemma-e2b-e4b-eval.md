## 판단 (임시)
- **E4B가 말은 더 낫지만 첫 글자까지 2배 느리고 메모리를 6GB 쓴다.** 12GB 폰에서도 다른 앱이 밀려나 스왑이 생긴다 → 기본값은 E2B 유지, E4B는 '깊은 대화' 선택지 후보.
- 프롬프트 손질은 효과가 있었다(캐묻기 해소). **가벼운 말 철학화는 프롬프트만으로 다 안 잡힌다** — 다음 후보: 일상 화제일 때 이어 말하기 줄이기(조율 규칙, 시안 명세 확인 필요), 말투 예시에 가벼운 답 넣기, 온도 낮추기 비교.
- 측정 방법 교훈: **평가 중 화면이 꺼지거나 다른 앱이 앞에 오면 속도가 1/4 아래로 떨어진다.** 평가 중엔 화면 켜짐을 유지하게 했고(디버그), 앞화면 여부를 15초마다 기록한다. 품질 반복은 노트북 llama-server로 한다(휴대폰 불필요, 6문장 2분 반).

## 다시 하는 법
```bash
# 휴대폰 (AGORA가 맨 앞, 화면 켜진 상태에서)
adb shell "am start -n app.agora/.MainActivity --es dev_model gemma-4-E2B_q4_0-it.gguf --ez dev_eval true"
adb logcat -s AGORA-eval:I        # 'saved <경로>' 가 나오면 끝
adb shell "run-as app.agora cat files/eval/<파일>.md" > qa/device-logs/eval/<파일>.md
# 노트북 (llama.cpp b11706 Windows 판, 같은 GGUF)
llama-server.exe -m gemma-4-E2B_q4_0-it.gguf --jinja -c 4096 --port 8080 -t 8 --no-webui
./gradlew :tools:pc-harness:run --args="llama-server gemma-4-E2B-laptop"
```
