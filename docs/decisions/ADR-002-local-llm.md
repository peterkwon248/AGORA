# ADR-002 · 로컬 LLM 런타임·모델 후보와 검증 절차

- 상태: **제안(Proposed)** — 실기기 측정 전까지 어떤 값도 확정하지 않음
- 날짜: 2026-10-14
- 관련: 지시서 5.3·9.2, 설계서 19.2·22.3·22.4, ONB-001~004

## 1. 런타임 후보 (2개를 같은 기기·같은 문장으로 비교)

| 후보 | 장점 | 우려 |
|---|---|---|
| **llama.cpp** (GGUF, NDK·JNI) | 모델 선택 폭이 가장 넓음(Qwen·Gemma·기타), 양자화 다양, 커뮤니티 측정 많음 | JNI·CMake 빌드를 직접 관리, 스트리밍·취소를 직접 구현 |
| **LiteRT-LM** (Google, Kotlin API) | Kotlin에서 바로 Engine 생성, GPU/NPU 백엔드, MediaPipe LLM Inference의 후속(MediaPipe 쪽은 유지보수 모드) | 지원 모델이 `.litertlm` 변환본으로 제한, 타이밍·토큰 수를 콜백으로 주지 않아 측정은 logcat에서 |
| (참고) MLC LLM, ExecuTorch | | Sprint 0 범위 밖. 위 둘이 모두 실패할 때만 |

`InferenceProvider` 뒤에 두므로 런타임을 바꿔도 앱 코드는 바뀌지 않는다.

## 2. 모델 후보 (한국어·영어 + 상업 배포 가능 라이선스)

| 후보 | 크기대 | 라이선스(배포 전 원문 재확인) | 비고 |
|---|---|---|---|
| Qwen3 1.7B / 4B 계열 | 1~3GB(4bit) | Apache 2.0 | 다국어·한중일 학습 비중 높다는 평가 |
| Gemma 4 E2B / E4B | 기기용 | Apache 2.0 (2026-04 공개) | LiteRT-LM 경로 유력. 공개된 독립 스마트폰 측정은 아직 적음 |
| Gemma 3n E2B / E4B | 기기용 | Gemma 이용약관 | LiteRT-LM 공식 지원 |
| 제외 | — | EXAONE 계열(비상업 라이선스), Kanana(온프레미스 별도 계약) | 한국어는 강하지만 배포 조건이 맞지 않음 |

> 한국어 철학 대화 품질을 같은 기기에서 비교한 공개 자료는 찾지 못했다 → **우리 평가셋으로 직접 잰다.**

## 3. 검증 절차 (Sprint 0)

**준비**
1. 기기 정보 기록: 모델명, SoC, RAM, Android 버전, 남은 저장공간
2. 모델 파일 내려받기 → SHA-256 기록 → 앱 전용 저장소에 배치 (저장소에 커밋하지 않음)

**측정 (모델 × 런타임 조합마다, 같은 프롬프트)**
| 지표 | 방법 |
|---|---|
| 모델 로드 시간 | 앱 로그 타임스탬프 |
| 첫 토큰까지(TTFT) | 요청 시각 → 첫 토큰 콜백 |
| 초당 토큰 | 출력 토큰 수 ÷ 생성 시간 |
| 피크 메모리 | `adb shell dumpsys meminfo <pkg>` |
| 발열·배터리 | `dumpsys battery` 온도·잔량, 10분 연속 대화 전후 |
| 취소 | 생성 중 취소 → 실제로 멈추기까지 시간, 부분 문장이 저장되지 않는지 |
| 강제 종료 | 백그라운드 전환·재진입 시 크래시 여부 |

**품질 (사람이 읽고 판정 — 자동 점수만으로 판정하지 않음)**
- 평가 문장 13개(설계서 22.3) × 한국어/영어, 특히 유재하 문장
- 니체·쇼펜하우어 각각 같은 입력에 답하게 해 **말투·관점이 구별되는가**
- 니체가 쇼펜하우어의 *실제 직전 발언*을 받아 말하는가
- 사실을 모르면 지어내지 않는가(유재하 생애 세부를 꾸미지 않음)
- 한국어 말투 수준(하오체·해요체)을 지키는가

**판정 기준(통과선)** — 측정 후 이 ADR에 수치로 적는다. 지금 숫자를 정하지 않는다.

## 4. 이 PC에서 할 수 있는 사전 작업 (실기기 측정을 대신하지 않음)
이 PC에는 Ollama(qwen2.5:7b)가 이미 있다. 이걸로 **프롬프트·말투 지침·조율 규칙**을 먼저 다듬고, 같은 GGUF를 휴대폰에 올려 비교하면 휴대폰 시간을 아낄 수 있다. PC 결과는 '실기기 측정'으로 보고하지 않는다.

## 결과
측정표(`qa/device-logs/`)와 함께 1순위·2순위 조합을 확정한다. 모두 품질 미달이면 대안(더 큰 모델·지식 검색 보강·Plus 우선)을 보고하고 대규모 구현을 보류한다(지시서 게이트 G0).
