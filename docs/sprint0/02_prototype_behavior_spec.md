# 02 · 시안 동작 명세 — 실제 엔진이 지켜야 할 것과 옮기면 안 되는 것

> 근거: `03_engine.js`(339줄)·`04_component.js`(1618줄)·`01_data.js`·`02_seed.js` 전체 판독. 2026-10-14.
> 시안의 답변은 **미리 쓴 문장**이다. 여기서는 그 문장이 아니라 *누가·언제·몇 번 말하는가*의 규칙만 뽑는다.

## 1. 대화 조율 규칙 (Conversation Orchestrator가 보존할 행동)

1. **1차 응답자 선택**
   - `@멘션`이 있으면 멘션된 방 멤버 **전원을 멘션 순서대로** 먼저 답하게 한다.
   - 멘션이 없고 사용자가 철학자 메시지에 **답장**했으면 그 1명.
   - 둘 다 없으면 관련도 순위로 자동 선택. 개인톡·인사·감사·화제 변경·비공개·완화 요청은 **1명**, 3인 이상 단톡방은 **2명**, 그 외 1명. **직전 화자는 가능하면 제외**.
2. **완화('좀 더 부드럽게')**: 논쟁 성향이 높은 쪽(니체 → 쇼펜하우어)이 먼저 부드럽게 받는다. 이후 그 방은 논쟁 빈도 off·강도 gentle로 고정, 일상 화제가 나오면 해제.
3. **자율 이어 말하기 예산**: 단톡방만. 방 설정 `off/contextual/active` = **0/2/4턴**. 비공개·완화·인사·감사 메시지에는 0.
4. **이어 말하기 제약**: 같은 철학자 연속 발언 금지 · 다른 철학자에게 반응하려면 그 철학자가 **이미 이번 흐름에서 말했어야** 함(실제 최신 발언에 반응).
5. **논쟁 횟수 상한**: 빈도 `off/rare/normal/frequent` = **0/1/2/무제한(9)**. 강도 `gentle/balanced/rigorous`는 어조·논증 깊이 차이. gentle에서는 일부 반박이 아예 생략됨.
6. **예산이 남았는데 이어 말할 거리가 없으면** 아직 말 안 한 멤버 1명이 직전 화자를 받는 짧은 말 1개까지만.
7. **임시 초대 손님**은 이번 흐름에서 한 번 말한 뒤 퇴장(시스템 메시지). 말하지 않았으면 남음.
8. **'더 이야기하기'**: 최대 2턴 추가. *시안은 여기서 논쟁 상한·손님 퇴장을 빠뜨림 → 실제 앱은 1번 흐름과 같은 규칙 적용(버그 수정).*
9. **사용자 개입**
   - 사용자가 입력을 시작하면 생성 대기열을 **잠시 멈춤(hold)**, 입력을 지우면 재개.
   - 새 메시지를 보내면 진행 중 생성 **취소** + '새 메시지에 맞춰 흐름을 바꿨어요'.
   - 일시정지 / 재개 / 정지 / '다시 쓰게 하기'(정지된 턴 재생성).
   - 모든 지연 작업은 **흐름 토큰(rev)** 으로 묶여 낡은 콜백이 무시된다 → 실제 앱: `context_revision` + `generation_id` + 취소 토큰.
10. **잠잠해지면**: 단톡방에서 흐름이 끝나면 '대화가 잠잠해졌어요 · 조금 더 듣기 / 노트로'. 텍스트 3개 이상이면 **대화 노트 제안 카드를 방마다 한 번**.

시안의 키워드 정규식 화제 분류(music/meaning/work/daily/greet/thanks/soften/private/change/open)는 실제 앱에서 **보조 신호로 격하**한다. 완화·비공개·화제 변경처럼 *동작을 바꾸는* 의도는 규칙 기반 + 모델 분류로 이중 확인.

## 2. 노트·댓글·예약 규칙

- **대화 노트**: 기본 범위 = 오늘 날짜 구분선 이후, 또는 '여기부터 노트로'를 누른 메시지부터. 문장마다 **근거 메시지 번호**, 철학자 발언은 회색, 추정은 점선+'추정'. *시안은 요약이 아니라 인용 잘라붙이기 → 실제 LLM 요약으로 교체하되 근거 링크 형식 유지.*
- **다시 요약 = 항상 새 노트**(원본 id를 출처로 기록). 사용자가 고친 요약은 원래 노트에 보존.
- **노트 고치기**: 같은 note_id에 새 버전 추가. 새 노트 작성 중 초안은 700ms 디바운스로 그 노트에만 저장, 아무것도 안 쓰고 나가면 생성 안 함.
- **표시 날짜 변경**: 표시 날짜만 바뀌고 노트·댓글 연결 유지. 미래 날짜 선택 불가.
- **감상평**: 대화 노트를 처음 열면 감상평 입력이 열림. AI가 고치지 않음.
- **읽기 범위**: 나만 / 고른 철학자 / 모든 철학자. 범위에서 빠진 철학자의 예약은 즉시 취소.
- **자동 댓글 예약 만들기**: 자동 댓글 모드가 off가 아니고, 노트가 '나만'이 아니고, 초안이 아닐 때. 노트당 활성 예약 상한 `가끔=1, 적극적=2`. 후보 = 그 노트의 출처 방 멤버 → 나머지. 읽기 권한 없는 철학자·이미 댓글/예약 있는 철학자 제외. **본문을 미리 써서 저장**.
- **예약 시각**: 지금 + 3시간 + k×55분, 조용한 시간에 걸리면 조용한 시간 끝 + 30분 + k×20분.
- **게시 직전 확인 5가지**(시안 `checks` 문구): 노트가 있나 / 읽기 허락이 그대로인가 / 이미 같은 말을 했나 / 고친 뒤 낡지 않았나 / 설정이 그대로인가.
- **노트를 고치면** 예약을 '다시 확인 중'으로 → *시안은 표시만 바꿈. 실제 앱은 리비전 지문 비교 후 재생성 또는 취소.*
- **댓글 부탁하기**(수동): 같은 철학자의 예약이 있으면 그 예약을 취소하고 즉시 작성.
- 댓글은 스레드(부모 댓글) 구조, 삭제 시 하위까지.

## 3. 데이터 모델 대응 (시안 → 실제 앱)

| 시안 | 실제 앱 | 바꿀 점 |
|---|---|---|
| `journals[]` (kind user/conv) + `notes[]`(철학자) 분리 | 단일 `Note`(kind USER_AUTHORED / CONVERSATION_SUMMARY / PHILOSOPHER_REFLECTION) | 하나로 합치고 `author_type`+`author_id` 명시 |
| `day: 13`(정수), `date: '10월 13일 화요일'`(문자열) | `created_at_utc`, `display_local_date`, `creation_timezone` | 날짜를 **키로 쓰지 않음** |
| `access {mode, ids}` | `visibility` + `PermissionGrant`(목적별) | 이름 변경 + 목적(읽기·댓글·기억·클라우드) 분리 |
| `revs[{at,title,body,day}]` | `NoteRevision` | UTC 시각, 철학자 노트에도 리비전 |
| `reflection {t,time}` (노트당 1개) | `UserReflection`(노트당 N개) | 별도 엔터티 |
| 댓글 `{a:'me'|pid, parent}`가 노트 안에 중첩 | `NoteComment(note_id, parent_comment_id, author_type, author_id)` | 평면 저장, 부모는 같은 노트만 |
| `plans {jid, pid, day, at, prepared, status, rev, t}` | `ProactiveActionPlan(target_id, source_revision_fingerprint, deliver_after, expires_at, status, idempotency_key)` | UTC 시각·만료·지문, 상태 SCHEDULED/POSTED/CANCELLED_STALE/CANCELLED_PERMISSION/DUPLICATE/EXPIRED |
| 개인톡 선제 메시지 = 그냥 메시지(`ca5`) + 시스템 줄 | 같은 `ProactiveActionPlan`(action_type=PROACTIVE_DM) | 예약 엔진으로 통일 |
| 메시지 `time: '08:47'`, 날짜는 구분선 위치로 추정 | 메시지마다 `created_at_utc` | 날짜 구분선은 화면에서 계산 |
| 메시지 `t`는 시드할 때 고른 **한 언어 문자열** | 작성 언어 원문 한 번 저장 | 언어 전환 시 절대 다시 생성·번역하지 않음 |
| 방 이름·시스템 알림이 완성 문장으로 저장 | 시스템 알림은 **유형+인자**로 저장, 화면에서 문장화 | 언어 전환 시 자연스럽게 바뀜 |
| 철학자 id `so/ni/sh/ca/ci/au` | `socrates/nietzsche/schopenhauer/camus/cioran/marcus_aurelius` | `legacy_ids` 매핑 표 |
| 기억 출처를 '10월 12일 노트'처럼 **날짜로** 가리킴 | `source_refs`에 note_id·revision | 같은 날 노트끼리 구별 |
| 노트 `status: draft/saved/reviewed` 한 칸 | `draft_state` + `review_state` 분리 | 사용자 초안과 AI 요약 검토는 다른 개념 |

## 4. 그대로 옮기면 안 되는 것 (버그·시연 지름길)

1. **언어 바꾸면 데이터 전부 초기화** — 캔버스 prop 변경 시 `initial()` 재실행, 온보딩 언어 선택 시 `reseedLang`. 실제 앱: 언어 전환은 UI 리소스만 바꾼다. **회귀 테스트로 고정.**
2. **AI 응답 언어를 바꾸면 모든 방의 방별 언어 설정을 덮어씀** → 실제 앱: 방별 설정은 '기본값 따르기'일 때만 따라감.
3. 날짜 하드코딩: 10월·`WEEK=[11..17]`·'오늘=13일'·예약 day 13/14.
4. 시드 id 하드코딩: 댓글 은행 `j13a/b/c`, '왜 왔나요?'가 `j12` 고정 참조, `ca5`, `plaza/daily/nihil`.
5. 가짜 스트리밍(완성 문장을 30ms씩 잘라 보여줌) → 실제 토큰 스트림 + 정지 = 생성 취소.
6. '지금 받기'로 예약 즉시 게시, '다시 확인'은 표시만, 다운로드 진행률 난수, 내보내기·전체 삭제는 토스트만, 동의만 하면 Plus 활성, 신고는 로컬 배열.
7. '비공개야' 의도를 **표시만** 하고 기억 격리는 없음 → 실제 앱은 기억 쓰기 단계에서 범위 강제.
8. 새 메시지를 보내면 스트리밍 중이던 메시지가 **사라짐** → 실제 앱은 '멈춘 답'으로 남기고 부분 생성문을 완성 발언으로 저장하지 않음.
9. 완화·논쟁 상태가 화면 상태에만 있고 방 데이터에 저장 안 됨, 방 삭제 시 정리 안 됨.
10. `@니`처럼 한 글자 별칭이 다른 단어와 충돌 → 자동완성 선택 시에만 확정 바인딩, 직접 입력은 2자 이상 유효 별칭만.
11. 철학자 선제 연락을 **실제로 보내는 로직이 없음**(시드 메시지 하나뿐) → Sprint 4에서 예약 엔진으로 처음 구현.

## 5. 타이밍 (체감 기준값 — 실제 모델 속도와 별개로 UI 연출 참고)
첫 턴 전 0.42s · '쓰는 중' 0.65~1.3s · 턴 사이 0.52s · 재개 0.2s · 입력 지움 후 재개 0.3s · 토스트 2.6s(액션 있으면 4.2s). 실제 앱에서는 '쓰는 중'이 **모델이 실제로 생성 중인 동안** 켜진다.

## 6. 장면 26개 → 개발용 미리보기 진입점
홈 · 첫 실행 · 첫 실행·모델(46% 일시정지) · 광장 · 멘션(`@` 팝업) · 초대(`@쇼펜하우어`+초대 시트) · 이어 말하기(일시정지) · 논쟁(완화 칩) · 먼저 연락(왜 왔나요 시트) · 새 방(니체·카뮈) · 방 분위기 · 방 정보 · 나의 노트 · 새 노트 · 대화 노트(감상평 편집) · 노트 댓글 · 자동 댓글 예약 · 읽기와 댓글 · 사유 노트 · 사유 노트 상세 · 철학자 · 프로필(카뮈) · 설정 · Plus · 클라우드 동의 · 기억 · 모델. 시각 비교 테스트는 이 26개 상태를 같은 시드로 재현해 스크린샷을 뜬다.
